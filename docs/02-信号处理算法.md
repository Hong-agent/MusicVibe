# 02 · 信号处理算法

本文是整套系统的核心。所有常数、公式、流程均与真实实现一致。

---

## 0. 关键前提：为什么不能"振幅直接跟随"？

一个最朴素的想法是：读出音频振幅，直接映射成马达强度。**这样做的效果很差**，原因有三：

1. **手机喇叭缺失低频，但马达需要它**——音乐里的鼓点能量集中在 40~120Hz，这段声波在手机扬声器上被衰减甚至削掉，直接取振幅会"抓不到鼓"。
2. **线性振幅 ≠ 打击感**——人耳（和手感）对强度是对数感知的，直接线性映射会让弱音震动过多、强音又不够突出。
3. **不同音源音量差异巨大**——同一首歌在不同平台母带电平能差 10dB，固定增益要么震不了要么一直饱和。

因此整套算法围绕这三个问题设计：**谐波提取**、**AGC 归一化**、**gamma 整形**。

---

## 1. 完整信号链（总览）

```
                        ┌──────────────── 振幅支路 ────────────────┐
右声道 x ─▶ 低通150 ─▶ 全波整流 ─▶ 带通100~1150 ─▶ RMS ─▶ 包络 ─▶ AGC ─▶ gamma ─▶ amp(0..1000)
                        └──────────────────────────────────────────┘
                        ┌──────────────── 脉宽支路 ────────────────┐
                        (同上 b) ─▶ 过零率 ─▶ 归一化 ─▶ 平滑 ─▶ pulseMs
                        └──────────────────────────────────────────┘
```

两条支路共用中间信号 `b`，一遍遍历完成，效率高。

---

## 2. 第 1 步：双二阶（Biquad）滤波器

所有滤波都用**双二阶 IIR + 双线性变换**实现，Q 固定为 `0.70710678`（Butterworth，最平坦响应），采样率 `fs = 48000`。

### 2.1 低通（Low-Pass）

用于"谐波源上限"：只保留 `sourceHighHz` 以下的能量。

```
ω  = 2π·f / fs
α  = sin(ω) / (2Q)
a0 = 1 + α
b0 = (1 - cos ω) / 2 / a0
b1 = (1 - cos ω) / a0
b2 = b0
a1 = -2·cos ω / a0
a2 = (1 - α) / a0
```

差分方程：

```
y[n] = b0·x[n] + b1·x[n-1] + b2·x[n-2] - a1·y[n-1] - a2·y[n-2]
```

### 2.2 高通（High-Pass）

用于"谐波带下限"：

```
b0 = (1 + cos ω) / 2 / a0
b1 = -(1 + cos ω) / a0
b2 = b0
a1 = -2·cos ω / a0
a2 = (1 - α) / a0
```

### 2.3 带通 = 高通 + 低通串联

本实现不直接用标准带通 biquad，而是**高通级联低通**（更直观，且能独立调上下限）：

```
带通(x) = 低通( 高通(x) )     // 低通用 hapticHighHz，高通用 hapticLowHz
```

### 2.4 级联（cascade）

`hapticCascade = 2` 时，带通再串一级（四阶），使频响更陡、更贴合 LRA 窄带谐振特性：

```
b = 带通( 带通( 整流(低通(x)) ) )
```

---

## 3. 第 2 步：全波整流 —— 谐波生成的核心

**这是整个算法最巧妙的一步。**

手机喇叭放不出 50Hz，但 X 轴线性马达的谐振频段通常在 **150~250Hz**，对 50Hz 几乎没反应。怎么办？

**用全波整流制造 2 次谐波。**

对信号取绝对值 `|y|`，数学上等于"平方后开方"，会在频谱中**生成原频率的 2 倍频能量**：

```
整流前：只有 50Hz 能量        → 马达不响（远低于谐振点）
整流后：50Hz 变成 100Hz 脉动   → 连带产生 100Hz、150Hz... 谐波
                              → 落在马达能响的频段！
```

具体过程：

```
y   = 低通150(x)      // 保留 150Hz 以下
rec = |y|             // 全波整流：低频鼓点 → 高频脉动
```

整流后信号再经带通（100~1150Hz）滤出目标频段：

```
h = 高通100(rec)      // 滤掉直流分量（整流引入的直流）
b = 低通1150(h)       // 限带，避免高频噪声
```

> **一句话**：整流把"听得见但震不动的低频"，搬到了"震得动"的频段。

---

## 4. 第 3 步：整帧 RMS —— 能量估计

每块音频算一个能量值：

```
rms = sqrt( (Σ b[i]²) / N )
```

- `b[i]` 是带通后的样本（同时用于过零统计）；
- `N` 是该块的样本数。

RMS 比峰值抗噪，比均值更能反映"打击的能量感"。

---

## 5. 第 4 步：非对称包络平滑

打击是**快起慢落**的。用一个"攻击/释放"非对称一阶低通来模拟：

```java
if (target > env)  env += (target - env) * rise;     // 上升快
else               env += (target - env) * release;  // 下降慢
```

- `rise`（默认 **1.00**）= 1 表示瞬时跟上，抓住每一个打击的瞬态；
- `release`（默认 **0.50**）控制余振长短，形成"咚——收"的手感；
- 调大 release → 振动更绵长连贯；调小 → 更干脆、跟拍更准。

---

## 6. 第 5 步：AGC 自适应增益（解决音量差异）

**这是"幅度感"的根基。** 用一个缓慢跟踪的峰值 `agcPeak` 做归一化：

```java
double agcPeak = 0.15;      // 初值

// 每块更新（人声/鼓点能量上升快、回落很慢）
if (env > agcPeak)  agcPeak += (env - agcPeak) * AGC_ATTACK;   // 0.35
else                agcPeak += (env - agcPeak) * AGC_RELEASE;  // 0.004

// 归一化到 0..1
double norm = env / agcPeak;
norm = clamp(norm, 0.0, 1.0);
```

### 为什么 attack 快、release 慢？

- `AGC_ATTACK = 0.35`（快）：峰值迅速跟上真正的鼓点，建立"当前这首有多响"的基准；
- `AGC_RELEASE = 0.004`（很慢）：即便有一段安静，基准也**不会**迅速掉下来——否则安静段会被误判成"相对很大"而乱震。

> **关键洞察**：AGC 归一化的是"相对于本曲峰值"的能量，不是绝对能量。这样不同音源、不同音量都能震在同一量程，动态才清晰。

---

## 7. 第 6 步：Gamma 整形（解决"多余的震动"）

归一化后 `norm` 在 0~1，但**如果直接线性映射，背景/伴奏/残响也会震**——这就是"多了很多无用的震动"。

解决：用指数 **> 1** 的 gamma 曲线**压低弱信号**：

```java
double shaped = Math.pow(norm, AMP_GAMMA);   // AMP_GAMMA = 2.2
```

曲线形状对比：

| norm（相对能量） | ^0.75（错误：抬升） | ^2.2（正确：压低） |
|---|---|---|
| 0.3（背景） | 0.45 | **0.07** |
| 0.5（人声/伴奏） | 0.59 | **0.22** |
| 0.8（较强鼓点） | 0.83 | **0.61** |
| 1.0（满拍） | 1.00 | **1.00** |

设门槛为 0.5（对应 amp=316，见下节），则：
- `norm = 0.5` 的伴奏 → `shaped = 0.22` → **低于门槛，不震** ✅
- `norm = 0.9` 的鼓点 → `shaped = 0.79` → **高于门槛，震** ✅

> **gamma > 1 = 只在该震时震。** 这是消除杂散震动的关键。

> 反直觉点：很多人第一反应是用 `< 1` 的指数去"增强弱信号"。在本系统里这是**错误**的——因为 AGC 已经把动态拉满了，再抬升弱信号只会让背景乱震。

---

## 8. 第 7 步：振幅映射

```java
int amp = (int) (shaped * MUSIC_GAIN * 1000);   // MUSIC_GAIN = 1.2
```

- `shaped ∈ [0,1]`，乘 1000 得到 `amp ∈ [0, 1200]`；
- **注意：这里故意不截断到 1000**，让驱动器统一处理（见 [06 踩坑](06-踩坑与设计权衡.md#坑-3双重截断导致断续)）；
- `MUSIC_GAIN`（默认 1.2）是整体轻重旋钮：>1 让强拍能顶满，<1 整体变轻。

---

## 9. 第 8 步：过零率 → 脉宽（频率感）

振幅给了"强度"，但缺"音色"。解法：用**过零率**估计信号频率高低，映射成振动**脉宽**。

```java
// 统计 b 的符号翻转次数
if ((b >= 0.0) != (prevB >= 0.0)) zc++;

// 过零率 → 归一化频率指标
double zeroRate = (double) zc / frames;
double normFreq = clamp(zeroRate / FREQ_ZERO_RATE_REF, 0.0, 1.0);  // REF = 0.25

// 跨块平滑（避免脉宽逐块跳变造成抖动）
freqSm += (normFreq - freqSm) * FREQ_SMOOTH;   // SMOOTH = 0.25

// 低频→长脉宽（钝重"嗡嗡"）；高频→短脉宽（清脆"哒哒"）
long pulseMax = cur.pulseMs;                      // 默认 600ms
long pulseMin = Math.max(8L, pulseMax / 6L);      // 最短 100ms
long pulseMs  = (long) (pulseMax - (pulseMax - pulseMin) * freqSm);

// 脉宽绝不小于块长，防止振动断续
long blockMsFloor = Math.max(20L, frames * 2L * 1000L / 48000L);
if (pulseMs < blockMsFloor) pulseMs = blockMsFloor;
```

### 为什么用脉宽模拟频率？

X 轴线性马达**无法**被 Android 标准 API 直接设定频率，只能设振幅和时长。但"连续长振"听起来是低频"嗡"，"短促重复"听起来是高频"哒"——用时长可以**间接表达**频率感，且纯 App 可行。

> `FREQ_ZERO_RATE_REF = 0.25` 是标定值：过零率达到 0.25 即视为"最高频"。

## 10. 完整伪代码

```java
// ---- 初始化（仅一次）----
FilterCoeffs fc = new FilterCoeffs();
HapticProfile cur = loadParams();
fc.rebuild(cur);                    // resetState = true

double env = 0f;
double agcPeak = 0.15;
double freqSm = 0.5;

// ---- 每块循环 ----
while (running) {
    cur = maybeReloadParamsAndRebuildCoeffs(fc, cur);  // 参数变化时只换系数

    short[] buf = new short[chunk];     // chunk ≈ 480 帧 × 2 声道
    int n = audioRecord.read(buf, 0, buf.length);
    if (n <= 0) continue;

    double sum = 0; int cnt = 0, zc = 0;
    double prevB = 0;

    // 取右声道：奇数索引，步进 2
    for (int i = 1; i < n; i += 2) {
        double x = buf[i] / 32768.0;

        double y    = lowpass(fc, x);        // 谐波源上限低通
        double rect = Math.abs(y);           // 全波整流 → 2 次谐波
        double h    = highpass(fc, rect);    // 谐波带下限高通（去直流）
        double b    = lowpassBand(fc, h);    // 谐波带上限低通
        if (fc.cascade >= 2) b = lowpassBand(fc, b);  // 可选级联

        if ((b >= 0) != (prevB >= 0)) zc++;
        prevB = b;
        sum += b * b; cnt++;
    }

    int frames = Math.max(1, cnt);
    double rms = Math.sqrt(sum / frames);

    // 频率感
    double normFreq = clamp((double) zc / frames / FREQ_ZERO_RATE_REF, 0, 1);

    // 包络
    float target = (float) rms;
    env += (target - env) * (target > env ? cur.rise : cur.release);

    // AGC
    agcPeak += (env - agcPeak) * (env > agcPeak ? AGC_ATTACK : AGC_RELEASE);
    agcPeak = Math.max(agcPeak, 1e-4);
    double norm = clamp(env / agcPeak, 0, 1);

    // gamma + 增益
    int amp = (int) (Math.pow(norm, AMP_GAMMA) * MUSIC_GAIN * 1000);
    amp = Math.max(amp, 0);

    // 脉宽
    freqSm += (normFreq - freqSm) * FREQ_SMOOTH;
    freqSm = clamp(freqSm, 0, 1);
    long pulseMax = cur.pulseMs;
    long pulseMin = Math.max(8L, pulseMax / 6L);
    long pulseMs = Math.max(
            (long) (pulseMax - (pulseMax - pulseMin) * freqSm),
            Math.max(20L, frames * 2L * 1000L / 48000L));

    driver.driveRaw(amp, pulseMs);
}
```

## 11. 常数速查表（信号处理）

| 常数 | 值 | 含义 |
|---|---|---|
| `fs` | 48000 Hz | 采样率 |
| `Q` | 0.70710678 | Butterworth |
| `AGC_ATTACK` | 0.35 | AGC 峰值上升系数 |
| `AGC_RELEASE` | 0.004 | AGC 峰值回落系数（很慢） |
| `AMP_GAMMA` | 2.2 | 振幅 gamma 指数（>1 压低弱信号） |
| `MUSIC_GAIN` | 1.2 | 振幅总标定 |
| `FREQ_ZERO_RATE_REF` | 0.25 | 过零率归一化基准 |
| `FREQ_SMOOTH` | 0.25 | 频率指标跨块平滑 |
| `agcPeak` 初值 | 0.15 | AGC 峰值初值 |
| 脉宽下限 | max(20ms, 块长) | 防断续 |
| 最短脉宽 | pulseMs/6 | 高频最短 |
