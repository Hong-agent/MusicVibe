# 03 · 参数体系与默认值

## 1. 参数一览

全部参数集中在 `HapticProfile`（不可变数据类）中，由 `SoundParams` 负责持久化。

| 参数 | 代码字段 | 中文 | 默认值 | 滑块范围 | 作用 |
|---|---|---|---|---|---|
| 谐波源下限 | `sourceLowHz` | 低频下潜 | **30** | 25–80 | 越低，低频下潜越深 |
| 谐波源上限 | `sourceHighHz` | — | **150** | 固定 | 谐波提取的截止频率 |
| 共振带下限 | `hapticLowHz` | 震动频宽下限 | **100** | 100–4000 | 触觉带通下沿 |
| 共振带上限 | `hapticHighHz` | 震动频宽上限 | **1150** | 100–4000 | 触觉带通上沿 |
| 触觉增益 | `hapticGainDb` | 震动强度 | **12** | 0–20 dB | dB 强度（显示用/标定用） |
| 门槛 | `vibeThreshold` | 响应门槛 | **0.50** | 5%–80% | 低于此值不震动 |
| 包络上升 | `envelopeRise` | 响应上升 | **1.00** | 0.20–1.00 | 越大越灵敏/跟拍 |
| 包络下降 | `envelopeRelease` | 响应下降 | **0.50** | 0.20–1.00 | 越大余振越长 |
| 总增益 | `energyGain` | 总增益 | **40** | 5–60 | 全局放大 |
| 振动时程 | `pulseMs` | 振动时程 | **600** | 80–1200 ms | 低频时的最长脉宽 |
| 跟随音量 | `followVolume` | 跟随系统音量 | **true** | 开关 | 音量越小震越轻 |
| 级联阶数 | `hapticCascade` | — | **1** | 固定 | 1=二阶，2=四阶 |
| 回退分支 | `fallbackLowpassHz/HighpassHz/GainDb` | — | 100 / 40 / 3 | 固定 | 非谐波回退路径 |

## 2. 默认预设（MUSIC）

```java
public static final HapticProfile MUSIC = new HapticProfile(
        30, 150,          // 谐波源 30-150Hz
        100, 1150,        // 共振带 100~1150Hz
        12f,              // 触觉增益 12dB
        0.50f,            // 门槛 50%
        1.00f, 0.50f,     // 包络：上升 1.00，下降 0.50
        100, 40, 3f,      // 回退分支
        1,                // 触觉带二阶
        40f,              // 能量总增益 40
        600L,             // 单次振动时程 600ms
        true);            // 跟随系统音量
```

## 3. 参数分组讲解

### 3.1 频段类（决定"抓到什么"）

- **`sourceHighHz = 150`**：谐波提取的低通上限。设太高会把中高频也纳入，导致振动"浑浊"；150Hz 能干净地抓住鼓点主能量。
- **`hapticLowHz = 100` / `hapticHighHz = 1150`**：带通范围。
  - 下限 100Hz 是刻意选的：整流后的鼓点能量主要落在 100Hz 以上；
  - 上限 1150Hz 是较窄的区间，聚焦打击瞬态、避免高频嘶声被转成振动。
  - 早期版本曾用 850~1150（很窄）或 400~4000（很宽），最终 100~1150 兼顾了下潜与干净度。

### 3.2 动态类（决定"震多强"）

- **`hapticGainDb = 12`**：dB 域强度，主要作为显示与心理标定。真正的幅度放大由 `energyGain` 与 `MUSIC_GAIN` 完成。
- **`energyGain = 40`**：能量总增益。不同机型马达灵敏度差异大，此值用于适配。
- **`vibeThreshold = 0.50`**：**最影响体感的参数**。门槛越高，只有越明显的打击才震；越低，杂散震动越多。默认 50% 是"只对明显打击响应"的平衡点。

### 3.3 时间类（决定"多跟拍"）

- **`envelopeRise = 1.00`**：最大，瞬时抓住打击瞬态。
- **`envelopeRelease = 0.50`**：中等，形成自然的"咚—收"。
- **`pulseMs = 600`**：最长脉宽（低频时）。高频时自动缩短到 1/6（约 100ms）。

### 3.4 开关类

- **`followVolume = true`**：跟随系统媒体音量。音量 0 → 不震；音量满 → 全强度。让用户在安静环境下调小音量时，振动也同步变轻。

## 4. 滑块映射机制

UI 用统一精度映射，避免每参数单独写换算：

```
滑块刻度：0 .. 1000（SLIDER_MAX = 1000）

value → progress:  t = (v - min) / (max - min)，clamp 到 [0,1]，× 1000
progress → value:  t = progress / 1000，v = min + t × (max - min)
```

即所有参数都线性映射到 0~1000 的滑块刻度。整数参数（Hz、ms）取整即可。

## 5. 参数即时生效机制

### 5.1 签名（signature）

把所有参数拼成一个字符串作为"指纹"：

```java
public static String signature(Context c) {
    return getSourceLow(c) + "|" + getGainDb(c) + "|" + getThreshold(c) + "|"
         + getRise(c) + "|" + getRelease(c) + "|" + getBandLow(c) + "|"
         + getBandHigh(c) + "|" + getEnergyGain(c) + "|" + getPulseMs(c) + "|"
         + getFollowVolume(c);
}
```

### 5.2 采集线程的变更检测

```java
String sig = signature(this);
while (running) {
    String newSig = signature(this);
    if (!newSig.equals(sig)) {
        sig = newSig;
        cur = SoundParams.build(this);
        fc.rebuild(cur, /*resetState=*/false);   // ⚠️ 关键：不复位状态！
        driver.setProfile(cur);
    }
    // ... 读音频、处理 ...
}
```

> 拖动滑块后，**下一个音频块（约 10ms）即生效**，无需重启服务。

## 6. 默认值迁移机制（DEFAULTS_VER）

问题：SharedPreferences 会一直保存用户上次的值，导致**新版本的默认值永远不会生效**。

解法：一个版本号，版本不符就清空旧存储：

```java
private static final int DEFAULTS_VER = 7;   // 每次改默认值 +1

private static SharedPreferences prefs(Context c) {
    SharedPreferences p = c.getApplicationContext()
            .getSharedPreferences(PREFS, Context.MODE_PRIVATE);
    int ver = p.getInt(K_DEFAULTS_VER, 0);
    if (ver != DEFAULTS_VER) {
        p.edit().clear().putInt(K_DEFAULTS_VER, DEFAULTS_VER).apply();
    }
    return p;
}
```

**发布新版调过默认值时，务必 +1**，否则装机后仍是旧值。

## 7. 调参哲学（重要）

| 你想要的效果 | 调整方向 |
|---|---|
| 震得太猛/太吵 | 降低 `vibeThreshold` 的反面 → **提高**门槛；或降 `MUSIC_GAIN` |
| 还有零星多余震动 | **提高** `AMP_GAMMA`（如 2.2 → 2.6） |
| 该震的鼓点漏了 | **降低** `AMP_GAMMA`（如 2.2 → 1.8）或降门槛 |
| 整体偏轻 | 提高 `MUSIC_GAIN` 或 `energyGain` |
| 拖尾太长 | 减小 `pulseMs` 或 `envelopeRelease` |
| 不够跟拍 | 减小 `envelopeRelease`，`envelopeRise` 保持 1.0 |
| 低频不够"沉" | 降低 `sourceLowHz`（如 30 → 25） |

> **调参顺序建议**：先定门槛（决定"震不震"）→ 再定 gamma（决定"杂不杂"）→ 最后定 gain（决定"多强"）。
