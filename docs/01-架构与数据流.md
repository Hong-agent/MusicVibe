# 01 · 架构与数据流

## 1. 系统总览

「震感音乐」是一个纯 App 方案（**无需 root、无需 Xposed、无需改内核**），其本质是：

```
┌─────────────────────────────────────────────────────────────┐
│                         用户手机系统                            │
│                                                               │
│  ┌──────────┐   系统混音    ┌──────────────────────────────┐  │
│  │ 音乐/视频 │ ───────────▶ │  AudioFlinger（系统音频输出）    │  │
│  │  App     │              └──────────────┬───────────────┘  │
│  └──────────┘                             │                   │
│                                    AudioPlaybackCapture       │
│                                           │ (MediaProjection) │
│  ┌────────────────────────────────────────▼───────────────┐  │
│  │                  震感音乐 App                            │  │
│  │                                                          │  │
│  │  MainActivity ──授权──▶ MusicCaptureService（前台服务）    │  │
│  │                              │                            │  │
│  │                        AudioRecord (48k/16bit/立体声)      │  │
│  │                              │ 每 ~10ms 一块              │  │
│  │                     ┌────────▼─────────┐                  │  │
│  │                     │  信号处理链        │                  │  │
│  │                     │  滤波/整流/包络    │                  │  │
│  │                     │  AGC/gamma/脉宽   │                  │  │
│  │                     └────────┬─────────┘                  │  │
│  │                              │ (振幅 0..1000, 脉宽 ms)     │  │
│  │                     ┌────────▼─────────┐                  │  │
│  │                     │  MusicVibeDriver  │                  │  │
│  │                     └────────┬─────────┘                  │  │
│  └──────────────────────────────┼───────────────────────────┘  │
│                                 │ VibrationEffect.createOneShot │
│                        ┌────────▼────────┐                      │
│                        │  X 轴线性马达    │ ──▶ 机身 / 桌面共振  │
│                        └─────────────────┘                      │
└─────────────────────────────────────────────────────────────┘
```

## 2. 模块职责

| 模块 | 职责 | 关键点 |
|---|---|---|
| **MainActivity** | UI + 授权 + 参数面板 | 请求 `MediaProjection` 屏幕录制授权（系统强制，每次启动都要） |
| **SoundParams** | 参数持久化 + 变更检测 | SharedPreferences 存储；`signature()` 生成参数指纹 |
| **MusicCaptureService** | 前台服务：采集 + 信号处理 + 驱动 | 核心；独立采集线程；参数即时生效 |
| **MusicVibeDriver** | 振幅 → 马达指令 | 门槛过滤、0..255 映射、去抖重发 |
| **HapticProfile** | 参数不可变数据类 | 默认预设 + `with()` 覆盖式构造 |

## 3. 线程模型

只有一个额外的后台线程，结构极简：

```
主线程 (UI)
  ├─ 拖动滑块 → SoundParams.save() → 写 SharedPreferences
  ├─ 点击"开启" → 获取 MediaProjection 授权 → startForegroundService()
  └─ 点击"停止" → stopService()

music-capture 采集线程 (Service 内)
  └─ while (running):
       1. 读参数签名（检测变化，变则重建滤波器系数，**不复位状态**）
       2. AudioRecord.read() 取 ~10ms 音频块
       3. 遍历样本做信号处理 → 得到 amp(0..1000) 与 pulseMs
       4. MusicVibeDriver.driveRaw(amp, pulseMs)
```

**为什么单线程就够？**
- 每块只有 480 帧（10ms），信号处理是几十次乘加，CPU 占用极低；
- `AudioRecord.read()` 本身会阻塞等待数据，天然形成节拍，无需额外调度；
- 只有一个写 SharedPreferences 的 UI 线程和一个读它的采集线程，用"参数签名"轮询即可解耦，无需锁。

## 4. "所有参数即时生效"的数据流

这是本项目一个很重要的体验设计：**没有"保存"按钮，拖动滑块立刻生效**。

```
[UI 线程]                          [采集线程]
拖动滑块
  │
  ▼
SoundParams.save(...)  ──写入──▶  SharedPreferences
                                       ▲
                                       │ 每块读取
                                  signature(c)
                                       │
                              与上次 sig 比较
                                       │
                            不同 → 用新参数重建
                            （hapticProfile.with(...)）
                                   + 重算滤波器系数
                                   （保留滤波器历史状态！）
```

关键点在于：**参数变更时只更新滤波器系数，绝不复位滤波器状态**。这一点极其重要，详见 [06-踩坑与设计权衡](06-踩坑与设计权衡.md#坑-2参数变更导致完全不震动)。

## 5. 数据流：从声波到振动

一段 10ms 音频块在信号链中的完整旅程（数值来自真实运行日志）：

```
右声道样本 x (float, 归一化到 ±1)
   │
   ├─ 低通 150Hz ─────────▶ y          保留下潜低频
   │
   ├─ 全波整流 |y| ────────▶ rect       产生 2 次谐波能量
   │
   ├─ 带通 100~1150Hz ─────▶ b          "搬到"马达频响区间
   │
   ├─ 整帧 RMS ────────────▶ rms       本块能量（示例 0.0075）
   │
   ├─ 包络平滑(rise/release)▶ env       时间连续的能量曲线
   │
   ├─ AGC 归一化 ──────────▶ norm      相对峰值（示例 0.48）
   │
   ├─ gamma 整形 ^2.2 ─────▶ shaped    压低弱信号（示例 0.20）
   │
   └─ ×1000×MUSIC_GAIN ────▶ amp       最终振幅（示例 240）

   同时：b 的过零率 → normFreq → 平滑 → pulseMs（脉宽）
```

最终 `driveRaw(amp, pulseMs)` 把它变成 `VibrationEffect.createOneShot(pulseMs, level)` 的调用。

## 6. 权限与系统要求

| 项目 | 值 |
|---|---|
| 最低系统 | **Android 10 (API 29)** — AudioPlaybackCapture 从 API 29 开始提供 |
| 目标系统 | API 34 |
| 必需权限 | `VIBRATE`、`RECORD_AUDIO`、`FOREGROUND_SERVICE`、`FOREGROUND_SERVICE_MEDIA_PROJECTION`、`POST_NOTIFICATIONS`(API 33+) |
| 运行时授权 | **MediaProjection 屏幕录制授权**（系统弹窗，用户每次启动需确认一次） |
| root | **不需要** |

> ⚠️ `MediaProjection` 授权是 Android 的硬性要求，无法绕过、无法静默。UX 上要做好引导文案："此授权仅用于捕获系统音频，不会录制屏幕内容"。
