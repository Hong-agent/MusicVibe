## 1. 音频捕获（无需 root）

### 1.1 MediaProjection 授权

`AudioPlaybackCapture` 必须依附于一个 `MediaProjection`（屏幕录制权限）。虽然我们**不录制屏幕**，但这是 Android 强制的"凭证"。

```java
// MainActivity：请求授权
MediaProjectionManager mpm = (MediaProjectionManager)
        getSystemService(MEDIA_PROJECTION_SERVICE);
projectionLauncher.launch(mpm.createScreenCaptureIntent());
```

用 `registerForActivityResult` 接收结果：

```java
private final ActivityResultLauncher<Intent> projectionLauncher =
    registerForActivityResult(new ActivityResultContracts.StartActivityForResult(), result -> {
        if (result.getResultCode() == RESULT_OK && result.getData() != null) {
            Intent svc = new Intent(this, MusicCaptureService.class);
            svc.putExtra(EXTRA_RESULT_CODE, result.getResultCode());
            svc.putExtra(EXTRA_RESULT_DATA, result.getData());
            startForegroundService(svc);
        }
    });
```

### 1.2 构建 AudioRecord

```java
// Service 中：用授权凭证拿到 projection
MediaProjection projection = mpm.getMediaProjection(resultCode, resultData);

// 捕获配置：只捕获媒体/游戏/未知用途的音频
AudioPlaybackCaptureConfiguration config =
        new AudioPlaybackCaptureConfiguration.Builder(projection)
                .addMatchingUsage(AudioAttributes.USAGE_MEDIA)
                .addMatchingUsage(AudioAttributes.USAGE_GAME)
                .addMatchingUsage(AudioAttributes.USAGE_UNKNOWN)
                .build();

AudioFormat format = new AudioFormat.Builder()
        .setEncoding(AudioFormat.ENCODING_PCM_16BIT)
        .setSampleRate(48000)
        .setChannelMask(AudioFormat.CHANNEL_IN_STEREO)
        .build();

int minBuf = AudioRecord.getMinBufferSize(48000,
        AudioFormat.CHANNEL_IN_STEREO, AudioFormat.ENCODING_PCM_16BIT);

AudioRecord audioRecord = new AudioRecord.Builder()
        .setAudioFormat(format)
        .setBufferSizeInBytes(minBuf)                  // 低延迟关键！见 §3
        .setAudioPlaybackCaptureConfig(config)
        .build();

audioRecord.startRecording();
```

> **注意**：`USAGE_MEDIA` 覆盖绝大多数音乐/视频 App。某些 App 会设置 `setAllowedCapturePolicy(FALSE)` 主动禁止被捕获，此类内容无法震动，属于系统限制。

### 1.3 为什么取右声道？

- 立体声交错存储：左声道在偶数索引（0,2,4...），右声道在奇数索引（1,3,5...）；
- 取**单一右声道**而非左右混音，原因：
  1. 计算量减半；
  2. 避免左右相位相消导致低频抵消；
  3. 实测右声道能量通常与混音相当，不影响效果。

遍历：`for (int i = 1; i < n; i += 2)`，`n` 是样本总数（左右交错的 `short` 数组长度）。

## 3. 低延迟优化（重点）

**延迟是触觉体验的生死线**。若振动比声音慢 200ms，用户会感到明显的"脱节"。

### 3.1 延迟的三个来源与对策

| 来源 | 原始做法 | 优化做法 |
|---|---|---|
| 采集环形缓冲 | `minBuf × 2`（约 180ms） | **`minBuf × 1`** |
| 每次读取块大小 | 2048 帧（约 43ms） | **480 帧（约 10ms）** |
| 振动时长 | 固定 600ms | **随频率动态缩短**，且不小于块长 |

### 3.2 读数块计算

```java
private static int HardwareChunkFrames(int minBufBytes) {
    int byHardware = Math.max(1, minBufBytes / 4 / 4); // minBuf/每帧字节(4)/4
    int target = 480;                                   // 10ms @48k
    int frames = Math.max(target, byHardware);
    if (frames < 256)  frames = 256;                    // 防 read 空转
    if (frames > 1920) frames = 1920;                   // 上限 40ms
    return frames;
}
```

**为什么要夹取上下限？**
- 太小（< 256 帧）：`read()` 会频繁返回 0，线程空转烧 CPU；
- 太大（> 1920 帧）：单块处理耗时长，延迟上升。

### 3.3 脉宽不得小于块长

```java
long blockMsFloor = Math.max(20L, frames * 2L * 1000L / 48000L);
if (pulseMs < blockMsFloor) pulseMs = blockMsFloor;
```

若脉宽小于一次下发间隔，振动会在下一次下发前就结束，产生**"哒哒"断续感**。用块长作为下限可保证连续。

> 注意 `frames * 2` 是因为 `frames` 是"每声道帧数"，而块时长 = 帧数/采样率。

## 4. 驱动马达（MusicVibeDriver）

### 4.1 获取 Vibrator

```java
if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.S) {
    VibratorManager vm = (VibratorManager)
            context.getSystemService(Context.VIBRATOR_MANAGER_SERVICE);
    return vm.getDefaultVibrator();     // ⚠️ 默认振动器 = 通常不是 X 轴！
} else {
    return (Vibrator) context.getSystemService(Context.VIBRATOR_SERVICE);
}
```

> ⚠️ **重要提醒**：`getDefaultVibrator()` 返回的通常是 Z 轴转子/普通振动器。若要精确驱动 **X 轴线性马达（LRA）**，需用 `VibratorManager.getVibrator(id)` 遍历所有振动器，通过 `Vibrator.getId()` 与 `getCharacteristics()` 选择 LRA。本项目在多数机型上直接使用默认振动器已可获得体感，但精确选轴是进阶优化点。

### 4.2 振幅 → 马达指令

```java
public void driveRaw(int amp, long pulseOverride) {
    if (vibrator == null || !vibrator.hasVibrator()) return;

    // 输入可能 >1000（AGC 后不截断），先安全夹取
    if (amp > 1000) amp = 1000;
    if (amp < 0)    amp = 0;

    int threshold = (int) (p.vibeThreshold * 1000);   // 0.5 → 500
    if (amp < threshold) {
        if (lastAmp > 0) { vibrator.cancel(); lastAmp = 0; }   // 停掉残留
        return;
    }

    // 门槛之上重新归一化到 0..1000
    int norm = (int) ((amp - threshold) * 1000L / (1000 - threshold));
    norm = clamp(norm, 0, 1000);

    int level = norm * 255 / 1000;                    // 映射到 0..255

    if (p.followVolume) level = (int) (level * volumeScale());   // 跟随音量

    level = clamp(level, 1, 255);

    // 去抖：变化太小不重发，避免抖振
    if (Math.abs(level - lastAmp) < AMP_STEP) return;  // AMP_STEP = 3
    lastAmp = level;

    long pulse = pulseOverride > 0 ? pulseOverride : p.pulseMs;
    if (vibrator.hasAmplitudeControl()) {
        vibrator.vibrate(VibrationEffect.createOneShot(pulse, level));
    } else {
        vibrator.vibrate(VibrationEffect.createOneShot(pulse, VibrationEffect.DEFAULT_AMPLITUDE));
    }
}
```

### 4.3 门槛归一化背后的意义

为什么要"门槛之上再归一化到 0..255"？
- 若不归一化，`amp=500` 与 `amp=1000` 直接线性映射会占用一半以上动态范围，而实际大部分内容集中在门槛附近，导致"要么弱要么满"；
- 归一化后，**门槛之上重新铺满 0..255**，让门槛附近的细微变化也可见。

### 4.4 无振幅控制能力的设备

`hasAmplitudeControl()` 为 false 的马达只能开/关。降级用 `DEFAULT_AMPLITUDE`，此时只有时长变化、没有强弱变化。体验会打折扣，但不会崩。

## 5. 生命周期

```java
@Override
public void onDestroy() {
    running = false;                    // 1. 通知采集线程退出
    writeSharedAmp(0);                  // 2. 振幅归零
    if (audioRecord != null) {
        audioRecord.stop();             // 3. 停止录音
        audioRecord.release();          // 4. 释放资源
    }
    if (captureThread != null) {
        captureThread.interrupt();      // 5. 中断线程
    }
    if (vibeDriver != null) vibeDriver.release();   // 6. 停振
    super.onDestroy();
}
```

顺序很重要：**先停标志位，再停硬件，最后中断线程**，避免线程在音频已释放后还去 `read()`。

## 6. 选做：root 守护进程共享振幅

实现中还预留了一条"低延迟超级通道"：

```java
// 每帧把振幅写入 /data/data/<pkg>/files/vibe_amp，格式："时间戳 振幅"
private void writeSharedAmp(int amp) {
    long now = System.currentTimeMillis();
    if (now - lastSharedWriteMs < 10L) return;      // 限流 10ms
    // 原子覆盖写入 now + " " + amp
}
```

若存在一个 **root 守护进程**轮询该文件，可直接写 `/dev/input/eventX` 驱动马达，绕过 Android 振动 API，延迟更低、力度更线性。

- **无 root 时该文件无害**，App 仍用 Vibrator 自行驱动；
- 有 root 时可作为进阶加速通道。

这是完全可选的能力，不影响无 root 用户使用。

## 8. UI 结构（参数面板）

一个 `ScrollView` + `LinearLayout`，包含：

- 标题 + 说明；
- 「开启音乐振动」/「停止」按钮；
- 状态提示 `tvStatus`；
- 9 个参数：每个 = 一个 `TextView` 标签 + 一个 `SeekBar`；
- 1 个 `Switch`（跟随系统音量）。

滑块回调：

```java
bar.setOnSeekBarChangeListener(new SeekBar.OnSeekBarChangeListener() {
    @Override
    public void onProgressChanged(SeekBar sb, int progress, boolean fromUser) {
        if (initializing || !fromUser) return;   // 初始化期间忽略
        persist();        // 立即保存
        updateLabels();   // 刷新文案
    }
    // ...
});
```

> `initializing` 标志位很关键：`setProgress()` 会触发 `onProgressChanged`，若不加保护，初始化时会把所有参数写成默认值，覆盖用户已保存的设置。
